A Vector Database is a special type of database that stores information as vectors (numerical representations called embeddings) and allows us to search for information based on its meaning rather than just exact keywords.

Vector databases are widely used in AI applications, LLMs, RAG systems, semantic search, and AI agents.

ORIGINAL TEXT

"I love programming"

Embedding Model

Converts text into numerical representation

Vector / Embedding

[0.23, -0.45, 0.89, 0.12, ...]
Illustrative numerical values


A user asks:

"How can I learn to code?"

Your database contains:
- Document 1: "Best ways to start programming"
- Document 2: "How to cook pasta"
- Document 3: "Beginner's guide to software development"
A traditional keyword search might miss documents that don't contain the exact words in the query.

A vector database can identify that documents 1 and 3 are semantically relevant even though they use different wording.

The important distinction is that the vector database retrieves information, while the LLM generates the answer.


1. What is the difference between embeddings and vectors?
    Every embedding is a vector, but not every vector is an embedding.
    A vector is a collection of numerical values.
    This is a three-dimensional vector. It doesn't necessarily represent any semantic meaning.
    vector = [2, 5, 8]

    An embedding is a vector created by a model to represent something meaningful, such as text, images, or audio.
    text = "I love Python programming"
    embedding = [0.23, -0.56, 0.89, 0.12, ...]
    The embedding model generates numbers that encode learned features of the text.


    A vector is a mathematical representation consisting of numerical values, while an embedding is a vector generated by a trained model that captures meaningful relationships within data. Embeddings allow us to compare the semantic similarity of text, images, or other content.


2. What is cosine similarity?
    Cosine similarity is a mathematical technique used to measure how similar two vectors are based on the angle between them.
    It is commonly used in semantic search and RAG applications.

    Simple example
        Imagine these three sentences:
        - A: "I love programming."
        - B: "I enjoy writing code."
        - C: "The weather is beautiful."
        Although A and B use different words, their meanings are similar.

        An embedding model might generate vectors whose directions are close together for A and B.
    
    Cosine similarity measures the directional similarity between two vectors using the cosine of the angle between them. In RAG systems, we use it to compare the embedding of a user's query with stored document embeddings and retrieve semantically relevant content.


3. How is a vector database different from SQL and MongoDB?
    SQL databases like PostgreSQL and MySQL are optimized for structured data, relationships, transactions, and exact queries.

    SELECT *
    FROM employees
    WHERE department = 'Engineering';

    This retrieves employees whose department matches the filter.

    MongoDB is a document-oriented NoSQL database that stores flexible JSON-like documents.

    db.employees.find({
        department: "Engineering"
    });

    MongoDB is useful when different records have flexible or nested structures.

    Vector databases are designed to efficiently store, index, and search embeddings.

    "Who works on machine learning projects?"

    A vector search could retrieve a profile mentioning "AI development and predictive modeling" even without matching the exact wording.


    SQL databases are primarily designed for relational structured data, MongoDB is a document-oriented NoSQL database, and vector databases are optimized for similarity search over high-dimensional embeddings. They can complement each other, and modern databases like PostgreSQL and MongoDB also provide vector search capabilities.


4. How do you handle metadata filtering and hybrid search?
    Metadata filtering restricts vector search to documents that match specific conditions, such as tenant ID, category, permissions, or date. Hybrid search combines semantic vector retrieval with keyword search, often using BM25 and rank fusion, to improve relevance for both conceptual questions and exact terms.


5. Can a vector database eliminate LLM hallucinations?
    No. A vector database can help reduce hallucinations, but it cannot eliminate them.

    what is hallucination?
        An LLM hallucination occurs when the model generates information that is incorrect, fabricated, or unsupported.

        For example:

        User asks:

        "What is our company's refund policy?"

        The LLM doesn't have the policy, so it invents an answer:

        "Customers receive a full refund within 90 days."

        This answer could be completely wrong.

        How does a vector database help?
        In a RAG system, we retrieve relevant documents and provide them as context to the LLM.

        For example:
        Without retrieval
        Question: "What is the refund policy?"
        LLM: "The refund window is 90 days."
        Potentially fabricated answer

        With retrieval
        Retrieved policy: "Refunds are available within 14 days of purchase."
        LLM: "According to the refund policy, customers can request refunds within 14 days."
        Answer grounded in retrieved evidence

        But hallucinations can still happen if the retrieved information is irrelevant, outdated, contradictory, or misunderstood by the LLM.



Vector databases don't use only cosine similarity. They can use different similarity or distance metrics.

The three most common are:
1. Cosine Similarity
2. Euclidean Distance (L2)
3. Dot Product (Inner Product)

We don't necessarily use only cosine similarity in vector databases. We can also use Euclidean distance and dot product.

Cosine similarity is commonly preferred for semantic search because it measures the angle between embedding vectors rather than their magnitude. This makes it useful for identifying text with similar meaning, even if their vector lengths differ.

However, the best similarity metric depends on how the embedding model was trained."

One thing to remember: The embedding model creates the semantic representation. Cosine similarity simply measures how similar those representations are.
